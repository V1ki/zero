# ZeRo session 真实任务评估：2026-09-06

本轮按用户指定来源读取 **ZeRo 的 `.zero` session**，从 11 个来源会话中选出 **14 个真实任务片段：简单 4、中等 6、困难 4**。此前误用 Codex 历史整理的 10 题已退出当前清单，另存为来源不符的历史记录，不参与本次结论。

## 读取范围与计数

- 主来源：`.zero/logs/sessions.db` 的 `sessions`、`session_messages`，以 SQLite 只读连接、同一读取事务扫描。
- 辅助证据：`.zero/logs/sessions/<日期>/<session-id>/trace.jsonl`，以及选中会话提及的现存产物。本轮未调用历史工具、发送文件、合并 PR 或发布草稿。
- 数据库保存 722 个会话、127,979 条消息；过滤后有 7,687 条用户文本候选。后者包含追问、状态查询及重复需求，**不能称为 7,687 个独立任务**。
- 排除工具结果、control/notification、排队消息的系统包装、压缩摘要、文件到达提示与斜杠命令；按消息 ID/来源消息 ID 去重。排队中的真实追加要求保留。
- 频率窗口：北京时间 **2026-06-08 00:00 至 2026-09-06 00:00**，按消息时间筛选，不按会话创建时间。覆盖 159 个有用户文本候选的会话、1,496 条候选消息。
- 日志目录另有 1,143 个 session ID，其中 421 个未在现数据库中注册；本轮未将其拼回语料，也未从压缩前快照恢复已移除消息。统计不是全部历史需求的完整普查。
- 扫描只输出 ID、哈希和统计，不导出原始用户全文、工具参数/结果、系统提示词或凭据。入库需求采用人工脱敏转述。

## 有证据的历史问题

1. **已经回答，收尾判定仍重复续跑。** `sess_20260901_1906_fei_c92d` 的消息索引 9–21：两条真实问题“工程提效是什么”和“IO 点表是什么”，产生六条助手文本答复。trace 中有四次 `continue` 判定，反复声称另一个概念尚未回答；相关判定输入未包含前一条工程提效定义，后来又只看到当前答复的一部分。应测试主模型与收尾器的上下文覆盖，不把所有重复都归因于系统提示词措辞。
2. **验收维度缺失，先否认用户指出的问题。** `sess_20260904_0851_fei_f6e6` 的索引 219–245：首次只查章节号和跨章重复，声称没有大段正文重复；用户再次指出后才检查章内重复。本轮对现存文件独立复算：原版第 112 章 288 段 = 相同 96 段 × 3，第 115 章 327 段 = 相同 109 段 × 3；去重版分别保留 96、109 段，仍有 244 个章节标题。这是可构建精确 gold 的优先难题。
3. **文件生成被当作验收完成。** `sess_20260806_1415_fei_2a52` 首次交付 EPUB 后承认 XML 错误，用户继续指出宽度、留白、目录和引用问题，随后重做可重排版。现存两份文件的 XML 均能解析，说明旧路径内容已被修复；不能把今天的文件反推为初次交付版本。本轮未做 EPUBCheck 与阅读器完整验收。
4. **追加纠正没有立即生效。** `sess_20260726_0056_fei_8726` 用户已说“好像是 Screeps”，紧接的助手消息仍推荐 Bitburner，之后才改口。适合测试排队消息、过时回答与用户纠正的处理。
5. **本地文件存在不等于用户可下载。** `sess_20260904_0851_fei_f6e6` 中用户要求 CLI 发送后仍反馈无法下载，后续才声称改为真正文件消息。需要分别验证上传结果、发送结果和文件卡片，不能只判最终文字里出现“已发送”。本轮没有重新发送，也未验证客户端当前下载能力。

这些是历史观察和当前局部验证，不是旧版提示词的整体失败率。历史模型、工具、上下文和收尾逻辑均不同，不能拿历史结果直接与新提示词比较。

每题的 JSON 保留 session ID、原始用户消息 ID、零起始半开区间、消息内容哈希、trace 相对路径、工具调用计数、工具错误和后台错误数量、历史观察、待冻结输入和验收要求。同一会话包含不同主题时只取相关片段。

`remember-endpoint` 是接入信息回忆探针，应单独标记；其所属模型配置任务族的频率不代表这条记忆问题本身高频。价格题全部使用历史日期与冻结页面，不能把旧报价当作当前行情。

## 如何接入后续 benchmark

- **先接 4 类有明确判分依据的行为**：两个问题都回答后停止、用户纠正及时生效、章内重复检测、用户可下载的文件交付。它们覆盖简单任务与复杂验收，且失败信号清晰。
- 将原始材料冻结为可审阅、可复算的输入；涉及书籍、个人或业务数据时用获得授权的材料或保持结构的脱敏样本。历史助手答案只能用于恢复背景，不能自动成为 gold。
- 分成“固定工具结果回放”和“隔离环境执行”两层。前者比较提示词的理解、纠正、边界及收尾；后者验证文件、脚本和产物。PR 合并、发送和公众号草稿接口使用虚拟服务，不在生产账户复演。
- 同一案例的前后版本使用相同模型、工具契约、初始状态、消息注入时序和资源预算；继续使用 GPT-5.5、GPT-5.6 Sol、GPT-6，各版本至少重复 3 次。先报告产物正确率、虚假完成、无效续跑、用户纠正响应、空回复/恢复和耗时，再看文字质量。
- 主模型和收尾器分别冻结输入及版本；必要时做“旧/新主提示词 × 旧/新收尾逻辑”的对照，避免把运行时上下文修复当作提示词收益。
- 初选 10 个开发样本、4 个留出候选；首轮回放使用了游戏纠正题后，现为 11 个开发/校准样本、3 个未运行留出候选。同一 session 全部在同组；剩余留出候选已人工审阅，尚未用于模型运行或提示词优化，**不等于完全未见测试集**。公众号同模板、共享来源材料等近重复仍须在正式切分前聚类。
- 初选阶段所有题均未就绪。现已冻结其中 4 个执行子题及 2 个收尾诊断，接入 `--suite real` 并完成 36 次真实模型试验，见 [首轮回放报告](prompt-benchmark-real-20260906.md)。这不表示 14 个完整历史任务都已具备端到端回放条件。

全库还看到 145 条没有文本且没有工具调用的 assistant 存储消息。这个计数包含历史内部/中断等可能情形，**不能当作 145 次用户空回复，也不是空回复率**。此前上游空响应诊断及其结论保持独立，见 [空回复诊断](empty-response-diagnosis-20260906.md)。
