# ZeRo 真实 session 回放首轮：2026-09-06

本轮真实调用 GPT-5.5、GPT-5.6 Sol、GPT-6，共完成 **36 次试验**。复核评分后，新提示词 **0 胜、1 负、17 平**；没有空回复、供应商错误或超时。唯一确认的退步是 GPT-5.5 新版在工程需求表中把 FEED 阶段的 4 项计为 3 项。

## 唯一确认的模型错误

试验：`chatgpt/gpt-5.5 / real-workbook-summary / real-after-20260906 / rep 1`。

- 正确阶段数量：售前支持 4、项目移交 1、FEED阶段 **4**、项目执行 11、现场服务 2，总计 22。
- 新版输出：FEED阶段 **3**，其余正确，且仍写 `total: 22`；阶段分项合计只有 21。
- 旧版本题正确。新版的状态分布、计划做序号 14/15、空结论序号 9 均正确，因此是阶段漏计，不是整份数据无法理解。
- JSON 文件与最终回复都重复了这个错误。该案例可作为“分项合计与总数守恒”的明确回归信号。

这里的 gold 来自原始工作簿的独立 ZIP/XML 解析，未把历史助手的“22 项”直接当作答案。运行时只提供原始单元格导出，不提供 gold。

## 评分器误报及处理

初始自动报告另有 3 条 `authorized: false`，涉及 Sol 旧版的表格题、GPT-6 新旧版的重复检测题。实际原因是评分器在未支持的只读 `bun -e` 校验请求中，把 JavaScript 箭头 `=>` 误识别为 shell 文件重定向。

已修复引号内程序参数的识别，并添加只读箭头/比较运算符及实际重定向/删除的回归测试。随后对**全部 36 条原始记录统一重新计分**：

- 未重新调用模型，也没有挑选新的答案。
- 每条历史工具调用都在虚拟沙箱重新解释；断言模型当时看到的返回内容和错误标记完全一致，否则拒绝重新计分。
- 原始消息、工具观测、usage、时间和响应模型均逐条保持不变。
- 仅 3 条误报的授权检查与总通过状态被修正；GPT-5.5 的真实计数错误保留。
- 原始结果及初始自动报告原样保留；本报告采用独立复核目录中的更正结果，审计文件记录前后评分、脚本与数据指纹。

本轮另有 7 次“虚拟工具不支持该命令”的响应，模型随后完成了任务。通过不表示这些脚本实际执行过；工具限制和失败恢复均保留在记录中。沙箱从不执行任意 shell，因此本轮不验证真实脚本执行能力。

## 重跑及边界

冻结的书籍正文和原单元格材料放在忽略提交的 `.zero/benchmarks/real-replay-fixtures-v1-20260906/suite.json`；源码中仅保留清单和校验指纹。此文件需要随本地评估资料保留。读取真实题库时会检查指纹，修改输入后必须创建新数据版本并重建两侧快照。

```sh
bun run prompt:bench run \
  --baseline benchmarks/zero-runtime/fixtures/prompt-bench/real-before-20260906.json \
  --candidate benchmarks/zero-runtime/fixtures/prompt-bench/real-after-20260906.json \
  --models chatgpt/gpt-5.5,chatgpt/gpt-5.6-sol,chatgpt/gpt-6-astra \
  --reps 1 --concurrency 6 --reasoning medium \
  --max-steps 10 --max-tokens 4096 --empty-retries 1 --timeout-ms 240000 \
  --out .zero/benchmarks/real-replay-NEW
```

以后修改提示词，先用相同 `--suite real`、不同输出文件分别冻结基线和候选，再运行对照。用于版本验收时，建议至少每题 3 次，并继续增加来自不同会话的任务，特别是完整文件验收、工具失败恢复与长过程授权；不能把重复同题当作扩大独立任务覆盖。

本轮的结构化输出契约和冻结工具降低了环境波动，但也缩小了原任务：未转换 EPUB、未完整扫描/修复 244 章、未真实发送文件或发布公众号草稿。游戏纠正题已从留出候选转入开发/校准样本；其他 3 个留出候选尚未运行。

本轮结果不足以支持发布“新提示词质量已提升”的结论。后续应优先确认计数退步是否复现，以及真实运行时如何向收尾器传入已完成事项。
