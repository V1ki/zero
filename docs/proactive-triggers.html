从接入到实际投递

本页预演使用合成数据。要围绕真实事件提问，打开本机 Router 工作台。要调整监听和通知偏好，前往监听与收件箱。

  1. 1

    接通真实来源

    按仓库选择 GitHub 签名推送或轮询，可另接外部 CI。从 WXARC 长等待取回的微信文字中筛选所选会话。

    验收服务重启后续读，超过 200 条积压能追完，同一条事件不重复建任务。
  2. 2

    按情境选去向

    启用主动处理后，每项委托可选直接生成事实提醒或由 Agent 归纳。Router 按作息、在场状态与授权决定提醒去向。

    验收模型离线时，直接提醒仍可投递。网页提示可直达任务，也可在网页提醒记录翻阅多条委托的摘要。
  3. 3

    围绕事件继续问

    Router 有独立网页入口。可在通用对话中询问或提议修改一项偏好。选中具体事件，A2UI 卡片会呈现它的摘要、状态和可用动作。

    试一试先问「为什么选了这个去向」，再问「如果我不在电脑前呢」。刷新后回到同一事件，继续之前的对话。

实现时需要守住的边界

两条情境规则同时命中时会怎样？

在项目或委托中，上移需要优先的规则，保存后重新预演。工作日下午人在电脑前时，「普通事件在网页提醒」和「在场时无需提醒」都可能命中。把后者放在第一条，下一次符合条件的事件就会跳过提醒。任务记录会注明命中哪一层的第几条规则。临近截止的提前量默认 60 分钟，可由项目或委托调整。查看规则与授权边界

当前能实际使用哪些能力？

在配置页选择 GitHub 仓库和 WXARC 会话，保存工作时段、在场和通知偏好。在 Router 工作台预演已保存的规则，查看单条事件的 A2UI 卡片，用同一线程问清首次延后和最终投递的理由。对话中提出的偏好变更须在卡片上亲自确认。可以为同一来源创建多个委托，分别选择具体会话和可写文档。在任务详情里可以沿着同一事项查看历次事件、提醒与归档；在已授权的 IM 会话收到提醒后可按任务编号继续。工作台使用说明

有新线索，谁会接着办？

同一个 Issue 或 PR 再有进展，Router 把新线索排给之前的 Worker，带上它已经核实的结果。新事项先判断有没有具体问题可查。小 PR 可以先核查，简单致谢只记入网页。打开事件能看到为什么办、办到哪一轮、证据在哪里。查看跟进与授权说明

工作台怎样调查一条 GitHub 事件？

在失败事件卡点「查看 GitHub 事件详情」可核对本次尝试的作业和步骤，卡片会注明来源与读取时间。Checks 标注与可安全展示的运行器日志分开列出。若缺少日志读取权限，仍保留已核对的步骤。「对比此前的运行」会查询上一次重跑和同来源分支的历史记录。PR 评论卡可以打开原评论并查询当前 PR 状态。工作台使用说明

关掉网页，或者中途断线，会怎样？

Server 持续运行，接入器把事件、订阅匹配和读取位置一起提交。发送前重新检查时间、在场和权限。一次提醒保留一个投递意图。平台可能已接收但回执丢失时，显示「微信投递待确认」并停止重发，可到所选私聊核对编号。

如何确认仓库真的在推送？

在目标仓库注册可访问的 HTTPS 回调，再核对 Recent deliveries 的回执和 ZeRo 收件编号。本机验收用自己的密钥将一条真实 Actions 失败记录回放两次，收件箱和 Web 提醒各一条。公网注册与真实 GitHub 投递需在具体仓库完成。GitHub 与外部 CI 接入步骤 · 回放的失败运行

什么信息可以跨平台？

先按任务受众和数据范围筛选目的地，再选展示深度。微信私聊可以只说「有一项发布决定」，项目日志留在已授权的工作空间。WXARC 未命中的文字在本机过滤，卡片被转发也不会赋予新用户执行权限。

何时考虑 Swift 或蓝牙？

Mac 上可启用锁屏、空闲和蓝牙音频信号。锁屏或离席会阻止投到网页；蓝牙连接只补充已有的在场判断。设置中还可指定节假日与调休。Swift 客户端是可选入口。
